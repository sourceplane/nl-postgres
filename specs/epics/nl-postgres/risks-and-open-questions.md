# nl-postgres — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| NL-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the lanes' own steps in staged job trees (the migrations applied through a stand-in Supabase Management API over a real Postgres with Supabase's roles), and the built Worker served by `wrangler dev` over it. A live bootstrap needs a workspace with Cloudflare and Supabase connected and room for two Supabase projects (NL-E) |
| NL-B | The model is verified only against a stand-in | OPEN | The stand-in answers in Workers AI's JSON-mode shape, so the provider, the three structured outputs, the actions and the SQL path are real; what SQL a real Llama 4 Scout writes for a question — and how often it writes SQL the database must refuse — is not tested. A live build answers that; OpenAI's gpt-5.4-mini is one Worker secret away |
| NL-C | `040` on a real Supabase project | OPEN | The migration runs as `postgres` through the Management API: `CREATE ROLE`, `GRANT query_reader TO postgres WITH SET TRUE` (Postgres 16+), a function handed to `query_reader`. The e2e runs it as a non-superuser `postgres` with CREATEROLE on the runner's Postgres 16, and tests/db on PGlite (17); Supabase's own `postgres` role and supautils are not tested here |
| NL-D | Catalog metadata is visible to `query_reader` | ACCEPTED | Every role can read `pg_catalog` (table and column names, settings); `query_reader` can read no other table's rows and write nothing. The app has one table |
| NL-E | Two Supabase projects per product | ACCEPTED | Stage and prod are a project each; Supabase's free plan allows two active projects per organization. BOOTSTRAP.md lists it as a prerequisite |
| NL-F | The data is fictional until the owner loads CB Insights' list | ACCEPTED | CB Insights' list is not redistributed; the sample says it is fictional in the migration and on the page, and `csv-to-sql.mjs` turns the owner's download into a migration |
| NL-G | `workers-ai-provider` 3.x is deprecated | ACCEPTED | Its successor is built around AI Gateway; the 3.3.1 binding provider is what AI SDK 6 takes, rag-chatbot and nuxt-ai-chatbot use the same package, and tests/web runs the real provider against a fake binding in JSON mode |
| NL-H | `react-hooks/immutability` is off | ACCEPTED | `components/dynamic-chart.tsx` reassigns its prop, the template's code, kept as written; the rule is new in eslint-config-next 16 |
| NL-I | A query's `date` comes back as an ISO date string | ACCEPTED | The rows travel as JSON from `run_read_only`; upstream's `@vercel/postgres` gave the page `Date` objects, which `components/results.tsx` formats with `toLocaleDateString()`. Dates now show as `YYYY-MM-DD` |
